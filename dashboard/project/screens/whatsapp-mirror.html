Two surfaces, one attention

WhatsApp and the dashboard, compared.

The same event_stream attention rendered three ways — as an offer in chat, as a live update in chat, and as a block on the dashboard. The question: should they mirror, replace, or complement each other?

Each surface is good at a different thing. WhatsApp is narrow, synchronous, verbal. The dashboard is wide, asynchronous, visual. The recommendation: complement — each surface carries the shape it handles best, and no attention is visible twice.

Three stances. Complement wins.

The same attention is well-served by different surfaces at different lifecycle moments. Don't force one surface to carry both shapes.

Stance What it means Pros Cons
Mirror Every offer and every update appears on both WhatsApp and the dashboard. Acting on one clears the other. Strongest consistency. User never misses anything. Highest implementation cost (real-time sync). Doubles Donna's writing budget. Feels redundant.
Replace Dashboard carries everything that isn't urgent. WhatsApp reduces to urgent pings and reach_out approvals only. Cleanest product. Dashboard becomes the primary object. No duplicate authoring. Loses WhatsApp-first ergonomics. Users who never open the web UI lose Donna's machinery.
Complement · recommended WhatsApp = event channel (live pings, reach_out approvals, chat-mode intent). Dashboard = object channel (offer review, brief reading, machinery, Living). Matches what each surface is already good at. No duplicate authoring. Natural routing per card type. Users need a mental model of "two places." Needs one clear rule for each attention type.
